# Симптом → причина → что делать

Сначала — где рвётся. Порядок проверки снаружи внутрь:
облачный фаервол → ufw → сервис `awg-quick@awg0` → ключи и обфускация пира → NAT и
форвардинг → DNS → MTU.

## Доступ к серверу

| Симптом | Причина | Что делать |
|---|---|---|
| SSH не пускает после правки | Ошибка в `00-hardening.conf`, `AllowUsers` без нужного пользователя | Из открытой второй сессии исправить; если обе закрыты — веб-консоль хостера под `<user>` по паролю |
| Поменял `Port` — ничего не изменилось | 24.04 слушает через `ssh.socket` | Править `ssh.socket` (`systemctl edit`, пустой `ListenStream=`), см. runbook 0.6 |
| `PasswordAuthentication no` не действует | `50-cloud-init.conf` прочитан раньше своего файла | Свой файл назвать `00-…`; проверять `sshd -T` |
| fail2ban всегда показывает нули | Нет `backend = systemd` | runbook 0.8 |
| Запер себя фаерволом | Правило ufw или облачного фаервола | Веб-консоль хостера; облачный фаервол — в панели |

## Модуль и сервис

| Симптом | Причина | Что делать |
|---|---|---|
| `modprobe amneziawg` — module not found | DKMS не собрал модуль: нет заголовков ядра, мало памяти | `apt install linux-headers-$(uname -r)`; swap есть? `dkms autoinstall`, смотреть `/var/lib/dkms/amneziawg/*/build/make.log` |
| После обновления и ребута туннель не поднялся | Новое ядро пришло без заголовков, модуль не пересобран | `linux-headers-generic` установлен? `dkms autoinstall`, ребут, `modinfo amneziawg` |
| Контейнер (`systemd-detect-virt` = lxc/openvz) | Модуль ядра не загрузить | Сменить тариф на KVM. Обход — userspace `amneziawg-go`, хуже и сложнее |
| `dkms status` показывает 1.0.0 | Метка из `dkms.conf` пакета | Версию смотреть в `modinfo amneziawg` |
| Ядро 7.0 / Ubuntu 26.04 — DKMS не собирается | Поддержка новых ядер отстаёт | Сервер — на 24.04. На ноутбуке — приложение AmneziaVPN, ему модуль не нужен |

## Нет хендшейка

| Симптом | Причина | Что делать |
|---|---|---|
| `awg show` — у пира нет `latest handshake` | UDP 443 закрыт в облачном фаерволе | Добавить правило; проверить `sudo tcpdump -ni eth0 udp port 443` — доходят ли пакеты |
| Пакеты доходят, хендшейка нет | Параметры обфускации клиента и сервера расходятся, неверный ключ сервера | Пересоздать пира через `awg-add-peer` — он берёт параметры из `obfs.params` |
| Linux: подключение через штатное окно VPN не работает | NetworkManager шлёт ванильный WireGuard, сервер молча отбрасывает | Приложение AmneziaVPN или `awg-quick` |
| AmneziaVPN на Ubuntu падает при старте | Нет `libxcb-cursor0` | `sudo apt install libxcb-cursor0` |
| Два устройства по очереди теряют связь | Один конфиг на двух устройствах | Отдельный пир на каждое |
| Роутер не поднимает туннель | Старый модуль в прошивке не понимает параметры | Проверить, что в `obfs.params` только классический набор; прошивка ≥ 4.9 |

## Хендшейк есть, интернета нет

| Симптом | Причина | Что делать |
|---|---|---|
| Пинг до `10.9.0.1` есть, до `1.1.1.1` нет | Нет форвардинга или NAT | `sysctl net.ipv4.ip_forward` = 1; `iptables -t nat -S POSTROUTING` — есть MASQUERADE; правило `ufw route allow in on awg0 out on eth0` |
| Внешний интерфейс не `eth0` | Другой хостер | `ip route show default`; поправить в `PostUp/PostDown` и правиле ufw |
| IP-адреса открываются, имена нет | DNS | `DNS =` в клиентском конфиге; резолвер доступен через туннель |
| Мелкие сайты грузятся, крупные и видео висят | MTU велик (часто PPPoE) | Подобрать MTU (runbook, Этап 2), выставить на сервере и клиентах |

## Работало и перестало

| Симптом | Причина | Что делать |
|---|---|---|
| Рвётся через минуты/часы, переподключение помогает | DPI по статистике или длинным потокам | Эскалация: порт и обфускация → новый IP → Reality (runbook, конец) |
| Не работает только у одного оператора | Блокировка у этого оператора | То же; второй оператор помогает отделить блокировку от сбоя сервера |
| У всех сразу | Сервер, IP или хостер | `awg-status`, `systemctl status awg-quick@awg0`, ребут, проверка модуля; ping сервера без туннеля |

## Утечки

| Симптом | Причина | Что делать |
|---|---|---|
| test-ipv6.com показывает адрес провайдера | IPv6 идёт мимо v4-only туннеля | На роутере выключить IPv6 на WAN и LAN; на клиенте — выключить IPv6 или добавить `::/0` в `AllowedIPs`, чтобы v6 уходил в туннель и там гас |
| dnsleaktest показывает DNS провайдера | Устройство берёт DNS мимо туннеля | `DNS =` в конфиге; на роутере — DNS через VPN; на Android выключить «частный DNS», если он не через туннель |
| Kill switch не режет при обрыве | Переключатель не включён или есть исключения в VPN Policy | Включить Block Non-VPN Traffic, убрать исключения, повторить эксперимент Этапа 4 |
